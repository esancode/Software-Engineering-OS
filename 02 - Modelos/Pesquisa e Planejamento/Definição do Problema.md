---

## 1. Problema (1-3 frases)
[Descreva o problema central de forma clara e direta. Ex: "Pequenos comerciantes perdem vendas porque não conseguem gerenciar pedidos de WhatsApp de forma organizada."]

---

## 2. Quem Tem o Problema (Personas/Perfis)

| Persona | Descrição | Dor Principal | Prioridade |
|---------|-----------|---------------|------------|
| [Ex: Dono de loja de roupas] | [30-50 anos, 1-2 func, usa WhatsApp Business] | [Organizar pedidos sem perder] | Principal |
| [Ex: Funcionário de loja] | [20-35 anos, usa celular da loja] | [Ver pedidos pendentes rápido] | Secundária |
| | | | |

---

## 3. Contexto de Uso
[Onde, quando, como a pessoa está quando tem o problema? Ex: "Durante o atendimento, recebe 20-50 msgs/dia, precisa anotar pedidos, conferir estoque, responder rápido."]

---

## 4. Consequências se NÃO Resolver
[O que acontece se o problema persistir? Seja concreto. Ex: "Pedidos perdidos, clientes insatisfeitos, retrabalho manual, estresse, perda de faturamento estimado em 15%."]

---

## 5. Necessidades Identificadas
> [!tip] Diferencie **necessidade** (resolve a dor) de **solução pedida** (o que a pessoa acha que quer).
> Ex: "Quero um app" = solução pedida. "Preciso não perder pedidos" = necessidade.

| Necessidade | Relacionada a Qual Consequência | Prioridade |
|-------------|--------------------------------|------------|
| [Ex: Centralizar pedidos em uma tela] | Pedidos perdidos | Alta |
| [Ex: Ver status de cada pedido] | Retrabalho manual | Alta |
| [Ex: Responder cliente rápido] | Clientes insatisfeitos | Alta |
| [Ex: Saber o que tem em estoque] | Pedidos de item sem estoque | Média |
| [Ex: Gerar relatório simples] | Perda de faturamento | Média |

---

## 6. Objetivo do Projeto
> Formato: "Este software permite que **[quem]** **[faça o quê]** para **[benefício]**."

[Ex: "Este software permite que **pequenos comerciantes** **gerenciem pedidos de WhatsApp em uma tela única** para **reduzir perdas em 80%**."]

---

## 7. Hipóteses Iniciais
> [!important] Hipóteses devem ser **falsificáveis** (testáveis na ETAPA 02).
> Formato: "Acredito que [X% / Y pessoas] [fazem/querem/precisam] [Z]."

| ID | Hipótese | Como Validar (ETAPA 02) | Prioridade |
|----|----------|-------------------------|------------|
| H1 | [Ex: Maior problema é organizar pedidos, não estoque] | Entrevistas: "Qual sua maior dor?" | Alta |
| H2 | [Ex: WhatsApp é canal principal para 90%+] | Perguntar: "Por onde recebe pedidos?" | Alta |
| H3 | [Ex: Pagariam R$ 50-100/mês] | Landing page teste / pesquisa disposição | Média |
| H4 | | | |
| H5 | | | |

---

## 8. Restrições Conhecidas

| Categoria | Restrição |
|-----------|-----------|
| **Técnica** | [Ex: Orçamento zero para infra. Uma pessoa desenvolve. Precisa rodar no celular.] |
| **Tempo** | [Ex: MVP em 4 semanas] |
| **Orçamento** | [Ex: $0 hospedagem, ferramentas gratuitas] |
| **Conhecimento** | [Ex: Sei React/TS, não sei Go/Rust] |
| **Legal/Regulatório** | [Ex: LGPD se dados pessoais] |
| **Outras** | [Ex: Cliente exige tecnologia X] |

---

## 9. Indicadores de Sucesso
> Como você saberá que o problema foi resolvido? Métricas mensuráveis.

| Indicador | Baseline (Hoje) | Meta (Pós-MVP) | Como Medir |
|-----------|-----------------|----------------|------------|
| [Ex: % pedidos perdidos] | ~15% | < 3% | Logs do sistema / relato usuário |
| [Ex: Tempo médio resposta] | ~10 min | < 2 min | Timestamp pedido → resposta |
| [Ex: Usuários ativos semanais] | 0 | 3+ | Analytics / login |
| [Ex: NPS / satisfação] | N/A | > 40 | Pesquisa pós-uso |

---

## 10. Soluções Existentes (Resumo Rápido - Detalhe na ETAPA 02)

| Solução Atual | Como Resolve | Limitação Principal |
|---------------|--------------|---------------------|
| [Ex: Anotar no papel] | Grátis, simples | Perde info, não escala |
| [Ex: Planilha Excel] | Organiza, grátis | Manual, não mobile |
| [Ex: App concorrente A] | Completo | Caro (R$ 200/mês), complexo |
| [Ex: Não resolve] | - | Perde vendas |

---

## Checklist de Conclusão (ETAPA 01)

- [ ] Problema descrito em 1-3 frases claras
- [ ] Personas identificadas (mínimo 1, ideal 2-3)
- [ ] Contexto de uso descrito
- [ ] Consequências listadas
- [ ] Necessidades separadas de soluções pedidas
- [ ] Objetivo do projeto escrito (formato padrão)
- [ ] Hipóteses registradas (mínimo 3, testáveis)
- [ ] Restrições conhecidas listadas
- [ ] Indicadores de sucesso definidos (mensuráveis)
- [ ] Soluções existentes resumidas
